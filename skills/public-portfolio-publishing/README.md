# Public Portfolio Publishing

**Type** Cowork skill, canonical reference  ·  **Trigger** A scheduled portfolio review, or any session publishing agent or skill documentation to the public repository

## What it does

Governs how work built and run privately gets described in the public agent portfolio, a fixed repository structure, a fixed set of document skeletons for deployments, skills and decision records, a naming law that renames every private, partner or platform-specific label into a description of what the agent actually does, and a language law that strips internal jargon, dates, commercial terms and any name beyond the operator's own.

## How it runs

Every private project maps to a public slug that describes its function, never a partner name, a platform name or a persona, and that mapping is fixed and consulted before any new item is drafted, never improvised per session. New deployments and skills are drafted in full but never pushed autonomously, they wait for a human sign-off before the folder is created. Existing public items are only ever touched for a material fact that actually changed, a resolved failure mode or a new measured number, never rewritten wholesale on a routine pass. Architecture decisions only get a permanent record where a real fork in the build actually happened, and once written that record is never edited again, a changed decision gets a new record that supersedes the old one instead. Every session that writes to the public repository re-reads what it just wrote and sweeps it for banned language before considering the write final.

## Guardrails

No internal economics, commission structure or margin ever appears in a public document, only output gains and removed failure modes. No name beyond the operator's own appears anywhere, no partner, no client, no colleague, no board or workspace identifier, no credential, no private link. Status on a public page changes only by the operator's explicit ruling, never from a routine review. Every existing decision record is treated as immutable except for a pure terminology correction, a change of mind gets a new record, never a rewrite of the old one. A public write that would shrink an existing file sharply, or that targets a file changed since it was last read, is refused rather than allowed to silently overwrite prior work.

## Lessons carried

A portfolio maintained by hand drifts, a slug picks up a partner's name because that was the fastest way to talk about it internally, a status line goes stale the moment the private project moves on, and the fix that held was mechanical, a fixed mapping table and a mandatory re-read-and-sweep step, rather than a style guideline trusted to memory each time. The first automated review proved the point in both directions, its sweep caught nothing because the law is mechanical, and its one autonomous status flip was reverted the same day and the law tightened, status is now the operator's call alone. Treating every public write as provisional until it survives its own sweep catches far more than treating the sweep as a final, separate step.
