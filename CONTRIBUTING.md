# Contributing

This repo documents production systems that run on one operator's real business, so its shape differs from a typical open-source project and the ground rules deserve stating plainly.

## What this repo accepts

Corrections, questions and challenges through [issues](../../issues). A factual error in a write-up, a broken link, a diagram that misleads, an architecture decision you would have taken differently, all of it is welcome and gets a reply.

Knowledge-base suggestions through issues too. The library takes anything that grows applied-AI builders, production architectures, talks, papers, pilots, businesses built around AI. Point at the source and say why it earns a folder.

## What lives outside pull requests

The deployment and skill write-ups describe private production systems, and every page ships through a documented publishing pipeline with its own review, naming and voice gates. A pull request against those pages would bypass the pipeline that keeps them accurate, so content changes to deployments/ and skills/ land through the pipeline, guided by whatever you raise in an issue.

## On the missing community files

There is no code of conduct, security policy or issue template here by decision. Those files manage contributor traffic on runnable codebases, and this is a documentation portfolio with a single maintainer. If the repo ever ships runnable code, they arrive with it.
